# Apple Watch Integration — Design

**Date:** 2026-07-04 (amended 2026-07-07: phases 1–2 shipped; added settings
toggle, wrist remote control as phase 6)
**Status:** Approved approach (A: workout session mirroring), phased delivery

## Goal

Give CrazyWork users with an Apple Watch live heart rate, measured (not
estimated) calorie burn, wrist haptic coaching, a glanceable workout display,
and proper Activity-ring credit — without changing anything for watchless
users. The phone remains the brain (camera, pose analysis, rep counting); the
watch is the body sensor and a second output surface.

## Context and constraints

- iOS deployment target is 18.0, Swift 6, project generated by XcodeGen
  (`CrazyWork/project.yml`). Watch target will be watchOS 11.0.
- The app already writes an `HKWorkout` with a MET-formula calorie estimate
  (`HealthStore.save`, `CalorieEstimator`) and reads body weight.
- Workout flow: `SessionCoordinator` emits `WorkoutEvent`s; `WorkoutAudioPlayer`
  (owning a `WorkoutAudioCoach`) turns them into speech/SFX. These are the
  integration points — the watch is a new consumer of the same events.
- No physical watch available during development: everything must be testable
  in the paired watch simulator (which can inject synthetic heart rate).
- The watch is strictly optional. No watch paired, watch app not installed,
  HealthKit denied, or mirroring fails mid-workout → the app behaves exactly
  as it does today.

## Architecture (Approach A: session mirroring)

When a workout starts on the phone, the phone asks HealthKit to launch the
watch companion app with a workout configuration
(`HKHealthStore.startWatchApp`). The watch runs the real
`HKWorkoutSession` + `HKLiveWorkoutBuilder` — it owns the heart-rate sensor,
the calorie math, and (once phase 2 lands) the saved workout, which is what
fills the Activity rings. The watch mirrors the session to the phone
(`startMirroringToCompanionDevice`), which gives both sides a built-in,
system-managed two-way data channel:

- **Watch → phone:** periodic metric snapshots (heart rate BPM, cumulative
  active energy kcal).
- **Phone → watch:** workout progress (exercise name, rep/second count,
  set index, phase) and haptic cue codes.

Rejected alternatives: DIY sync over WatchConnectivity (more code, flakier,
only benefit is pre-iOS-17 support we don't need) and passive HealthKit reads
(no live data — the watch only samples HR every ~5 minutes outside a workout
session).

## Components

### New watchOS target: `CrazyWorkWatch`

Added to `project.yml` (platform watchOS, deployment 11.0, embedded in the
iOS app). SwiftUI. Contains:

- **Session handling** — receives the launch configuration, starts
  `HKWorkoutSession` + `HKLiveWorkoutBuilder`, starts mirroring, forwards
  metric snapshots to the phone, ends/saves the session when told to (or when
  the phone session dies).
- **Workout view** — phase 1: minimal "workout in progress" screen with
  heart rate. Phase 4: exercise name, live rep/hold count, set x of y, rest
  countdown.
- **Haptics** — phase 3: plays `WKInterfaceDevice` haptic types keyed by cue
  codes from the phone.

### Shared message protocol: `Sources/Shared/WatchMessage.swift`

One small `Codable` enum compiled into both targets (a shared source folder,
not a new package — ChallengeCore stays pose-only):

- `metrics(heartRate: Double, activeEnergyKcal: Double)` — watch → phone
- `progress(exerciseName: String, value: Int, target: Int, setIndex: Int, setCount: Int, phase: SessionPhase)` — phone → watch, where `SessionPhase` is `active | resting | finished` (mirrors `SessionCoordinator.phase`)
- `haptic(HapticCue)` — phone → watch (`countdown`, `setComplete`, `restOver`, `workoutComplete`)
- `control(WatchControl)` — watch → phone (`skipRest`, `endWorkout`), phase 6
- `end` — phone → watch
- `ended(activeEnergyKcal:)` — watch → phone, acknowledges `end` with the
  measured total (drives the save-ownership rule)

Encoded with `JSONEncoder` over the mirrored session's data channel. The
codec round-trip is unit-tested.

### Phone side: `Sources/Health/WatchWorkoutMirror.swift`

An `@Observable` object owned by the live-workout flow:

- `start()` — requests watch launch + accepts the mirrored session. All
  failures are non-fatal and leave it in `.unavailable`.
- Publishes `latestHeartRate: Double?` and `watchActiveEnergyKcal: Double?`
  for the UI and the save path. `nil` heart rate = show nothing (today's UI).
- `send(_ message: WatchMessage)` — fire-and-forget; drops silently when no
  session is mirrored.
- `end()` — tells the watch to finish and save.

`LiveWorkoutView` reads `latestHeartRate` for display. `SessionCoordinator`
stays pure — it never learns about the watch; the view/flow layer forwards
its existing `WorkoutEvent`s into `WatchWorkoutMirror` the same way it feeds
`WorkoutAudioPlayer`.

## Data flow (steady state, phases 1–4)

1. User starts workout on phone → `WatchWorkoutMirror.start()` (best-effort).
2. Watch session begins; watch streams `metrics` every few seconds.
3. Phone camera loop → `SessionCoordinator.feed` → `WorkoutEvent`s → both
   `WorkoutAudioPlayer` (speech, unchanged) and `WatchWorkoutMirror`
   (`progress` + `haptic` messages).
4. Workout ends → phone sends `end` → watch finishes the builder and saves
   the `HKWorkout` (phase 2+).

## Save ownership (phase 2 decision rule)

Exactly one device writes the workout to HealthKit:

- Watch session ran and ended cleanly with measured active energy > 0 →
  **watch saves** (measured calories, rings credit). Phone writes nothing.
- Otherwise (no watch, mirroring failed, energy came back 0) → **phone saves**
  via the existing `HealthStore.save` + `CalorieEstimator` path, unchanged.

The phone knows which case it is in because `WatchWorkoutMirror` reports
whether the session ended cleanly with energy. This rule is unit-tested as a
pure function.

## Phases

Each phase is independently shippable and demo-able in the simulator.

1. **Foundation + live HR** — watch target, mirrored session, `metrics`
   messages, heart rate shown in `LiveWorkoutView`, minimal watch screen.
   HealthKit auth extended to read heart rate. *Done when: paired simulators
   show injected HR live on the phone during a workout, and a run with no
   watch behaves exactly as today.*
2. **Real calories + rings** — save-ownership rule above; watch saves the
   workout with measured energy. *Done when: workout saved from watch shows
   measured kcal in Health, and the phone-only fallback still saves the
   estimate.*
3. **Wrist haptics** — map coach-level events (3-2-1 countdown, set complete,
   rest over, workout complete) to `haptic` messages; watch plays distinct
   `WKHapticType`s. Rep-by-rep ticks are deliberately excluded (wrist-tap
   spam); revisit as a toggle if users ask. *Done when: countdown and set
   completion produce distinct taps in the watch simulator.*
4. **Glanceable wrist UI** — `progress` messages drive a live watch screen:
   exercise, rep/hold count vs target, set x of y, rest countdown. *Done
   when: the watch mirrors the phone's live state within ~1s.*
5. **HR analysis** — post-workout HealthKit query for HR samples in the
   workout interval; per-set HR curve in `SummaryView` (existing `ChartCard`
   component), effort/recovery trends in `StatsView`. Works for any workout
   with HR data regardless of phases 1–4. *Done when: a summary shows an HR
   chart for a workout that has samples and hides it for one that doesn't.*
6. **Wrist remote control** — users stand ~6 ft from the phone so the camera
   can see them; ending rest early or ending the workout shouldn't require
   walking back. New watch → phone `control` message with two commands:
   - `skipRest` — phone calls `SessionCoordinator.beginNextSet()` (the same
     thing the rest screen's completion does). Watch shows the button only
     while its last `progress.phase` is `resting`.
   - `endWorkout` — coordinator gains `finishEarly()`: record the in-progress
     set as a partial `SetResult`, set phase to `.finished`, emit `.finished`.
     The existing save path (including watch save-ownership) then runs
     unchanged. The watch asks "End workout?" with a confirm tap first —
     an accidental end discards nothing but is irreversible.
   Unknown/late `control` messages (e.g. skipRest arriving after rest ended)
   are ignored — the coordinator's phase guards already make them no-ops.
   *Done when: tapping Skip Rest on the watch simulator advances the phone's
   rest screen within ~1s, and End Workout lands on the phone summary with
   the partial set recorded.*

## Error handling

- `startWatchApp` fails (no watch, app not installed, auth denied): mirror
  enters `.unavailable`; UI shows no HR; save path falls back to estimator.
  No error surfaced to the user — watchless is a normal state, not a failure.
- Mirroring drops mid-workout: phone keeps coaching (camera and audio are
  phone-local); save ownership falls back to phone per the decision rule.
- Watch app killed / undelivered messages: all sends are fire-and-forget;
  the watch UI shows the last state it received.
- HealthKit heart-rate read denied but workout-write allowed: everything
  works except the HR display and phase-5 charts.

## Testing

- **Unit (phone):** `WatchMessage` codec round-trip; save-ownership decision
  rule; event→haptic mapping. All pure functions, live in `CrazyWorkTests`.
- **Simulator:** paired iPhone + Watch simulators; Xcode's simulated HR
  drives phases 1, 2, 5. Haptics verified via simulator logs/screen.
- **Hardware:** deferred until a physical watch is available; no design
  dependency on it.

## Settings (shipped 2026-07-07)

One toggle: "Use Apple Watch during workouts" (`watchWorkoutEnabled`,
`@AppStorage`, default on) in the Profile tab's Apple Health card, disabled
until Health sync is on. `LiveWorkoutView` starts the mirror only when both
`healthSyncEnabled` and `watchWorkoutEnabled` are set. No other settings:
haptics get a toggle only if users ask, and the watch has nothing else
configurable.

## Out of scope

- Starting workouts from the watch (the camera is the app; phone initiates).
  Controlling an already-running workout from the watch is in scope (phase 6).
- Watch complications, always-on-display tuning, standalone watch app.
- watchOS < 11 / iOS < 18 support.
- HR-reactive coaching ("slow down, zone 4") — possible later on top of
  phase 1 data; not designed here.
